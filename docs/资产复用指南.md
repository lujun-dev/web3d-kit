# 资产库使用指南（拼接优先）

这份仓库的做法是：**先把可复用的东西拆成小件，再靠拼接去搭场景**，
而不是直接让 AI 生成一整场景。原因很直白——

- 拆件是**可验证**的：件是死的，拼起来对不对可以用数字量（顶点数、包围盒、构图量测）核。
- 生成是**不可验证**的：出来一张图好看不好看全凭感觉，而且下一次生成不会更好，只会漂移。
- 拆件**越用越厚**：一个新场景只写它自己的装配，管线和素材不用重做。

## 一、仓库长什么样

```
assets/                     资产包（一件一文件，机械拆出，未改写实现）
  core/                     运行时底座
    world.js                世界与全部运行时状态（集中在一个 W 对象里）
    constants.js            常量与 GLSL 片段
    canvas.js               画布绘制助手（圆角、文字、地砖、导盲砖…）
    math.js                 随机数与杂凑（可复现）
    geometry.js             几何原语（盒/块/板/杆/管/线/灌木…）与桶合并
    materials.js            材质（toon / glass / ground / 灯）
    util.js                 工具（颜色解析、坐标换算、图集类 TextureAtlas、招牌时序…）
  regions/                  程序化贴图（canvas 画的，一张一文件）
  props/                    构件（便利店/邻楼/电线杆/自行车/猫… 一件一文件）
  systems/                  机制（雨三层、溅水、滴水、发光通道、地面反射、墨线合成、泛光调色、自动门…）
  scene/                    场景形状与**装配范例**（把资产件拼回一场完整雨夜街景）
  manifest.json             清单：每个部件的名字 / 所在文件 / 类别 / 行数
  region-list.json          贴图件的登记尺寸（宽 × 高）
  props-index.json          构件件的行数与登记信息
  region-list.json          贴图件的登记尺寸（宽 × 高）
  props-index.json          构件件的行数与内部 add* 调用数
kit/                        装配与自检工具
  blocks/registry.js        积木注册表 + 分轮（?step=1 几何 / 2 贴图 / 3 着色器与后处理）
  test/*.mjs                客观自检：出画量测、亮度直方图、特效是否真生效、零外链
tools/
  split-assets.py           拆分器（可复跑：从基准单文件重新生成整包）
  verify-assets.mjs         保真验证：把资产件拼回去打包 → 跑起来 → 对照顶点数/报错
docs/
  资产复用指南.md           本文件
  同类开源拆解.md           同类项目的做法拆解
```

## 二、用资产包拼一个场景（推荐姿势）

```js
// 1) 世界与运行时状态（引入即建好 renderer/scene/camera/controls）
import { W } from '../assets/core/world.js';
// 2) 只引你要用的件，别整包引
import { buildStoreShell } from '../assets/props/buildStoreShell.js';
import { buildThreeStoryHouse } from '../assets/props/buildThreeStoryHouse.js'; // 新写的件按同一格式放进来
import { createRain } from '../assets/systems/createRain.js';
import { drawRoofTiles } from '../assets/regions/drawRoofTiles.js';

// 3) 拼装：件都是普通函数，需要什么状态就从 W 里读写
W.atlasRects.roofTiles = W.atlas.register(256, 256, drawRoofTiles);
buildStoreShell();
createRain();
```

三条口径：

1. **先盘现成件**：写任何新几何/新贴图之前，先在 `assets/` 和 `manifest.json` 里找有没有现成的（同名、同用途、同风格）。
2. **不要改写件**：件是从原实现机械拆出来的，只搬移、不改逻辑；要改就**新增一个件**（例如 `buildThreeStoryHouse`），别动老件——老件被别的场景引用着。
3. **一次只加一味**：新场景先出体块（`?stage=1`）交人判，再加贴图（`?stage=2`），再开着色器与后处理（默认）。每轮都出图，好坏由人判，别一口气全上。

## 三、加新件（贴图 / 构件 / 机制）

1. 新文件放进对应目录：贴图 `assets/regions/`、构件 `assets/props/`、机制 `assets/systems/`，**一件一文件**，函数名 = 文件名。
2. 需要的运行时状态从 `W` 读写；需要别的件就直接 `import`，别复制实现。
3. 把件登记进 `manifest.json`（`tools/` 里的拆分器会自动做；手写件按同样的字段补一条）。
4. 跑 `node tools/verify-assets.mjs`：它会把整个包打成一个 HTML 跑起来，报错为零、桶顶点数对得上才算过。

## 四、保真怎么验（不靠肉眼）

| 手段 | 判据 |
|---|---|
| `tools/verify-assets.mjs` | 无 pageerror / console error；桶顶点数与基准一致（拆包改动的唯一合法理由是**新增**件，不该让老件数字变） |
| `kit/test/frame-check.mjs` | 关键点的屏幕坐标：关键点出画数 = 0 |
| `kit/test/look-check.mjs` | 亮度直方图（均值 / 分位 / 死黑占比 / 过曝占比）+ fps |
| `kit/test/effects.mjs` | 每个特效必须**可量测地**改变像素，否则判定为死代码 |
| `kit/test/compliance.mjs` | 单文件保证：无外链、无内联事件、无外部请求 |

## 五、对外发布纪律

- 资产包是**本地拆解产物**：不要在文档、注释、提交信息里写它来自哪份参照文件、作者或来源链接。
- 不提交任何非自有的原始素材（HDRI / PBR 贴图走 `assets.lock.json` + 重下脚本，不存本体）。
- 场景产物（HTML）保持单文件、离线可开：`kit/test/compliance.mjs` 会验这一条。
