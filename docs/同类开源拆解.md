# 同类开源拆解：他们怎么组织一个「three.js 微缩小景」

去看的是两个**方向相同**的开源项目（不是底层库）。结论先给：**同方向没有成熟积累，但有两个人把"组织方式"做得很干净，值得照搬**；而"发光通道 + 材质化反射 + 分轮"这套它们都没有——那是我们的空位。

---

## 1. flo-bit/stylized-dioramas（★1，2026-09 活跃，monorepo）

六个微缩景各占一个目录：`asia / island / italy-town / night-street / ruins / underwater`，每个是一个独立 Vite 工程。
其中 **`night-street`（《雨 — Ame Yokochō》）跟我们目标几乎重合**：雨夜、霓虹、水洼反射、断墙小巷，且声明"所有几何与贴图都在代码里生成，无下载模型/图片"——和我们同一条路。

### 1.1 文件组织（可直接照搬）

| 文件 | 行数 | 职责 |
| --- | --- | --- |
| `src/main.js` | 166 | 渲染器/灯光/相机/后期/交互（只装配，不做几何） |
| `src/diorama.js` | 530 | 几何、材质、装配、道具、水洼 |
| `src/textures.js` | 130 | 固定种子的程序化 Canvas 贴图与文字 |
| `src/weather.js` | 42 | 雨 + 涟漪（独立模块，可开关） |
| `scripts/check.mjs` | 96 | 冒烟测试：自起 vite(strictPort) → 等就绪 → Playwright 收 pageerror → 截图到 `artifacts/` |
| `README.md` | — | **含"文件职责表 + 按键表 + 缩放/交互说明"** |

即：**一个景 = 4 个源码文件 + 1 个冒烟测试 + 一张职责表**。比我现在的"大而全 kit + 单文件场景"更清晰。

### 1.2 值得直接学的技术点

- **正交相机**：`new THREE.OrthographicCamera(-8, 8, 6, -6, .1, 90)` —— 微缩模型感的来源之一（没有透视畸变）。我一直在用透视相机，这是白捡的一招。
- **雨**：600 条 `LineSegments`（每滴带长度与速度），位置数组每帧手写更新、`setUsage(DynamicDrawUsage)`；
  材质 `LineBasicMaterial({ color:'#9cb2c5', transparent:true, opacity:.065, depthWrite:false })`，雨丝带 `.015` 斜度。
  ——比我用精灵**便宜且方向更对**（线是拉长的，精灵是点）。
- **涟漪**：`InstancedBufferGeometry().copy(new THREE.RingGeometry(.84, 1, 32))` + `aOffset/aPhase` 实例属性 +
  12 行 shader：`age = fract(time*.55 + aPhase)`；`size = .014 + age*.15`；`fade = pow(1.-age, 2.)*.085`。
- **后期**：`EffectComposer + RenderPass + SSAOPass + UnrealBloomPass + OutputPass`；渲染器 `ACESFilmic + exposure 1.13`、
  `PCFSoftShadowMap`、`FogExp2('#17222e', .019)`。
- **确定性**：`rng(seed)`（与参照作品同款 mulberry32，两个项目都用）。
- **几何缓存**：`geometryCache = new Map()`，按尺寸缓存 `RoundedBoxGeometry(w,h,d,2,r)` —— 圆角盒子统一 0.025 半径。
- **道具函数形态**：`box() / cylinder(a,b,r) / pipe(CatmullRomCurve3 + TubeGeometry) / plane() / ring(TorusGeometry)`。
- **交互与无障碍**：`R` 雨 / `L` 霓虹 / `O` 自动环绕 / `0` 复位 / `S` 下载明信片 / `F` 全屏；`prefers-reduced-motion` 关动效；
  canvas 带 `aria-label` 与 `tabindex`。
- **测试形态**：自己 spawn vite（`--strictPort`）→ 轮询就绪 → `chromium.launch({ channel:'chrome' })` → 收集 `pageerror` → 截图。

## 2. moppius/contextual-dioramas（★24，MIT，2024-01）

组件式 + **真素材**路线（和我们"全程序化"相反，值得当另一条腿参考）。

- 组件：`Diorama / Terrain / Water / Biomes / Building / Tree / Cactus / Rock / ContextualObject / ContextQuadtree`
- 工具层：`WebGLApp`（渲染器与主循环）、`AssetManager`（**队列 + 并发 10 + 进度监听**，含 `loadTexture / loadEnvMap / loadGLTF`）、
  `customizeShader`（给任意材质统一加 `defines / uniforms / beforeCompile` 监听）、`ExponentialNumberController`
- 素材：`public/models/*.glb`（房子、仙人掌）+ `textures/equirectangular/cloud_layers_1k.hdr`
- 值得学：① AssetManager 的"队列 + 进度 + 并发"写法；② `ContextQuadtree`（按四叉树在上下文里撒物件，避免随机堆叠）；
  ③ `customizeShader` 这种"材质能力包装器"；④ 用真实 HDRI 做环境光（我们下载了素材却一直没用）。

## 3. 对我们（web3d-night-kit）的直接结论

1. **组织方式照搬第 1 家**：每个景 4 件套（`main` / `diorama` / `textures` / `weather`）+ `check.mjs` 冒烟测试 + README 职责表。
   kit 保留（它提供积木、图集、分轮、自检脚本），但**景的源码按四件套切分**。
2. **可直接搬的技术**：正交相机、LineSegments 雨 + 实例化涟漪、SSAOPass、几何缓存、按键/无障碍、冒烟测试形态、职责表。
3. **我们的空位**（这两家都没有）：发光通道系统（16 通道 + 顶点 aEmission）、地面材质化反射（斜裁剪 + LOD 模糊 + 竖向光条 +
   wetMap 三通道）、分轮工作法（几何 → 贴图 → 着色器）。这两条是我们相对同类的**差异点**，值得继续做深。
4. **一个提醒**：两家都用"固定种子 + 程序化贴图 + 零下载素材"，说明我们这条路不是孤例；但两家的景都**只有一块基地/一条巷子**，
   没有"多题材积木库"——我们要做的"积木化复用"在开源里确实没有现成答案。
